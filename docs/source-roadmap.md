# Source integration and storage roadmap

**Current implementation (26 September 2026):** `src/domain/contracts.ts` is the v1 Zod boundary. `src/server/nws.ts` supports point-filtered NWS weather, while `POST /api/v1/context/query` has CAL FIRE incidents, NIFC/WFIGS perimeters and AirNow observations (server key required), and `POST /api/v1/hazards/query` has the dated Glendale GIS MCP snapshot (server key required). **Production UI and all three personalized routes are paused** until source rights, caching, rate limits and monitoring are reviewed. The nonproduction `FIREPOINT_DEMO_LIVE_SOURCES=enabled` flag permits explicit-button integration testing only. A bounded 60-second NWS exact-point cache and notice-to-source-check link exist only in an **unmerged local draft**. No City/County evacuation feed, verified standing-zone lookup, permanent last-good cache, report service, source polling or cross-instance rate limit has shipped. Missing data is not safety. See [contract](contracts.md) and [source policy](source-policy.md).

## Build order and authority

1. **Official links and NWS weather (existing backend):** user initiates a query; show publisher, issue/expiry, source check status, applicable location from publisher and original [NWS API](https://www.weather.gov/documentation/services-web-api) record. NWS wind/fire weather is not an evacuation order. Need rate/abuse bounds, server logging review and a non-misleading UI before enabling it for residents.
2. **Active agency evacuations (next source research):** first verify the [LA County EOC/Genasys published warning-area item](https://www.arcgis.com/home/item.html?id=e8285c6509ec4269b5cd2aef02f41c8f) and its [FeatureServer layer](https://services.arcgis.com/RmCCgQtiZLDCtblq/arcgis/rest/services/Public_Emergency_Map_GENASYS_Alert_Warning_Area/FeatureServer/0). Its metadata describes approximately 10-minute refresh; status fields and Glendale jurisdiction must be checked with the issuer, as must the [LA County GIS terms](https://egis-lacounty.hub.arcgis.com/pages/terms-of-use). Then separately verify the [Cal OES active evacuation view](https://www.arcgis.com/home/item.html?id=c0dd2a8779764c26910b83a7e974ee66) and its [FeatureServer layer](https://services.arcgis.com/BLN4oKB0N1YSgvY8/arcgis/rest/services/CA_EVACUATIONS_CalOESHosted_view/FeatureServer/0). Cal OES is a statewide **aggregator**, not necessarily the issuing agency; the item describes a roughly 5-minute rebuild with a brief empty gap. Compare each record's `EDIT_DATE` with `STATEWIDE_LAST_UPDATED`, not a single freshness clock. [Metadata about public reuse](https://www.arcgis.com/home/item.html?id=3ba86748155e4582954d6a0c217ecd3c) is not unambiguous; seek Cal OES clarification. Separately check [Glendale Fire Know Your Zone](https://www.glendaleca.gov/government/departments/fire-department/other-links/emergency-preparedness-response/know-your-zone) for the official resident action. An empty *active* feed does not prove safety or establish standing zone boundaries. Retain original issuer links and do not merge records without verified IDs and status semantics.
3. **Standing preparedness geography (not live):** the [Glendale GIS MCP](https://github.com/HackerFund/GlendaleGisMcp) exposes a dated reference snapshot and optional hosted access; it is not a resident feed. Verify each layer's agency/source vintage, clip, rights, field semantics and geometry before publishing. City neighborhoods are not evacuation zones. Keep hosted bearer on the server only. The Mapbox basemap (when configured) is display context, not a data source for zone membership.
4. **Optional contextual lanes:** [CAL FIRE incident information](https://www.fire.ca.gov/incidents) offers [active incident points](https://incidents.fire.ca.gov/umbraco/api/IncidentApi/GeoJsonList?inactive=false); location and containment are not proof of safety. [NIFC/WFIGS public current perimeters](https://wfigs-nifc.hub.arcgis.com/pages/wfigs-public-data) include prescribed fire, may lag or omit polygons, and are **not** spread forecasts or evacuation lines; keep the publisher polygon time distinct from fetch time. Verify rights and on-map caveats before display. [AirNow](https://docs.airnowapi.org/) has a key and reporting-area/preliminary AQI with [use conditions](https://docs.airnowapi.org/docs/DataUseGuidelines.pdf), not address-level exposure; faithful AQI display is possible, but do not turn preliminary observations into unsupported guidance. [NOAA CPC ENSO](https://www.cpc.ncep.noaa.gov/products/analysis_monitoring/enso_advisory/ensodisc.shtml) is seasonal context, not live Glendale risk. Do not bundle these into an emergency verdict.
5. **Community observations (later):** prototype a private on-device draft first. A server receipt/public feed needs consent, abuse limits, human redaction/moderation, deletion/retention and takedown before launch. A moderated report remains unverified and must not become an agency notice or a map of “confirmed” fires.

## Deferred model source: WindNinja (research queue, not an alert API)

[USFS Fire Lab WindNinja](https://github.com/firelab/windninja) is open-source **terrain-adjusted wind modeling software**, not a public hosted REST alert feed. Its [official documentation and FAQ](https://ninjastorm.firelab.org/windninja/faq.html) describe a batch CLI (`WindNinja_cli`), example configurations, and a build-from-source Dockerfile; its [developer API](https://ninjastorm.firelab.org/windninjaapi/) is a **C interface**, not an emergency web service. Research a pinned release/container and a separate scheduled or on-demand job runner after the official-source lanes work. Do not query it as another notice adapter.

Possible **planning-only** inputs: a sourced DEM such as USGS 3DEP, a cited HRRR forecast or observed wind initialization, chosen solver/configuration and domain. Capture DEM source/vintage, HRRR cycle and valid time, WindNinja version (release 4.0.0 was current during the September 2026 research), solver, mesh, domain/buffer, run time, config hash and output speed/direction grid provenance. Model winds can feed a separately validated fire-spread study, but are **not** fire arrival, a current incident, an evacuation order, a risk rating or a safe route. Validate both solver options on a recorded Santa Ana event against canyon stations before showing even a planning wind layer. The fast mass-conserving solver can understate lee-side/downslope flow; [published downscaling evaluation](https://acp.copernicus.org/articles/16/5229/2016/) finds large lee-slope errors. Mark absent/stale results unavailable, never calm or safe. Keep this out of the resident MVP and show any eventual scenario only with assumptions, uncertainty, model lineage and a “planning projection, not a forecast” label.

## Contract upgrades before mixing feeds

An unmerged pre-public v1 draft ties each official notice's `sourceKey` to one unique `sourceChecks` entry, rejects an out-of-date `ok` check, and requires a named issuer before a notice can be labeled evacuation; coordinate with the API owner before merging it into the already-shipped v1 adapters. Before mixing feeds, **version the next wire contract** and add a source registry, publisher ID, jurisdiction and documented geometry/zone applicability, source as-of/vintage, upstream rights, dedupe/version linkage, and explicit stale/expired/retracted disposition. Keep source operator distinct from issuing agency. Each required source must produce a check even when down or missing, rather than deriving source health from the notices that happened to return. No-match is meaningful **only for verified coverage**; outside coverage, outage, stale, and unconfigured are distinct. Each number or status shown in UI should carry a trace to the original issuer URL and the check time. Write synthetic fixtures for partial pages, changing IDs, overlapping issuers, clock skew and feed rebuild gaps.

## Storage: hackathon vs durable service

- **Hackathon:** request-time server-only adapters and short, bounded caches can demo a few real sources with explicit stale/unavailable clocks; store only local checklist/optional coarse area on device. Never make a static JSON fixture of believable incidents. Do not put precise location in GET URLs, analytics or browser logs. A single Vercel/Next route is **not** a reliable scheduled poller or stdio MCP host.
- **If operating for residents:** a separate scheduled ingest worker records each attempt and a distinct last-success/complete generation for each allowlisted source. Validate and paginate GIS into staging; atomically publish a complete snapshot, retaining last-good on upstream outage, empty rebuild gap, partial pagination or schema drift. A managed Postgres/PostGIS store can hold source registry, original publisher IDs, geometries, versions and checks. Bounded private object storage can preserve source payload evidence with retention, access and license controls. A short server-only API queries authoritative polygon membership; publisher-less or approximate geometry yields only broad context. Backfill is for audit, never retroactive live safety.
- **Operations:** measure availability and drift per source, define stale thresholds by owner, review costs and data rights, enforce server-only credentials, rate-limit personalized queries, document incident response and run a manual agency acceptance check before any live-coverage claim. Never transform a zero-result fetch into “all clear.”
