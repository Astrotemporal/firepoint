# PWA storage, source pipeline, audio and route handoff

**Status:** this is an implementation choice guide, not deployed infrastructure. Firepoint currently has a Next.js 16 PWA manifest, a network-first service worker that caches only `/offline.html` and two icons, four locally saved checklist items, and an optional coarse Glenoaks Canyon label in `localStorage`. The page does not call the existing server-only NWS weather route. There is **no** IndexedDB store, durable ingestion worker, database, push sender, ElevenLabs endpoint, official evacuation-path service or predicted fire spread. The [source policy](source-policy.md) and [real-time-source rules](https://github.com/HackerFund/GlendaleGisMcp/blob/main/docs/real-time-sources.md#rules-for-using-real-time-data-in-an-app) apply before any new data reaches residents.

## Where data could live

| Layer | Good fit | Limits / release gate |
| --- | --- | --- |
| Device `localStorage` (**current**) | Tiny explicit checklist/approximate area choice and a clear/reset control. No account needed. | Synchronous and user-clearable; never store a secret or precise location by default. Browser storage may fail or be evicted. |
| Device [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API) (**future**) | Opt-in structured prep plans, unsent private drafts or a small *timestamped, schema-versioned* last-synced source view. | Validate after loading, cap space/retention, give a delete control. Offline saved source text is **not current**. Browser quotas/eviction are not a durable emergency record: [storage limits](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria), [WebKit policy](https://webkit.org/blog/14403/updates-to-storage-policy/). |
| Service-worker [Cache Storage](https://developer.mozilla.org/en-US/docs/Web/API/CacheStorage) (**current shell only**) | Versioned offline fallback and local static assets. | Do not silently cache agency APIs, personalized responses or Mapbox tiles. A cached empty feed cannot establish safety. Mapbox web offline rights require separate review. |
| Short server cache (**unmerged NWS draft only**) | A tested, bounded 60-second exact-point NWS response cache/single-flight would reduce repeated upstream calls, **separate** from a personalized `Cache-Control: no-store` response. | Not shipped on `main`; no cross-instance coordination or durable last-good record. Bound keys/size, protect precise points/logs, honor publisher cadence; add platform rate limits before a public UI. |
| Managed PostgreSQL + [PostGIS](https://postgis.net/docs/ST_Intersects.html) (**proposed**) | Source registry, publisher IDs/versions, verified footprints, attempt/last-success clocks, complete generations and geographic matching. | Separate scheduled worker and migrations; access controls, monitoring, retention, permission and cost review. Do not store resident addresses by default. |
| Private bounded object store (**proposed**) | Original agency payload evidence and hashes **where license allows**; reprocessing/audit by version. | Source rights, access/retention, encryption and takedown. Never serve raw private reports as a public feed. |

A separate ingest worker should validate and paginate each allowlisted source into staging, then publish a **complete** generation atomically. Record an attempt even when it fails; retain last-good with an explicit stale/down marker, not a fake empty-success. Do not treat a Cal OES rebuild gap or absent perimeter as an all-clear. The Next route remains a bounded server-only query layer, not a reliable poller. Preserve source operator versus issuing agency, original ID/URL/text, published/updated/source-as-of time, retrieved/last-success time, geometry/coverage, status/expiry, dataset vintage, payload hash and transformation/model version. Show a clear source check beside each item. Use the verified publishing footprint, not a basemap camera, for a point match. See [source roadmap](source-roadmap.md) and [contracts](contracts.md). An unmerged pre-public v1 draft links each notice to a named source check. Agree the field with the API owner before merge; the shared contract still needs jurisdiction/coverage semantics, source cadence controls and platform abuse limits before a resident live-feed UI.

## What a PWA does and does not add

Firepoint can be installed on a Home Screen, adapt to phone/tablet screens, open its cached **offline checklist fallback**, and retain manually chosen local prep items without accounts. With future code, the browser can ask permission for device location, notifications, camera, audio playback or locally stored drafts; none is automatic. On iOS/iPadOS 16.4+, [Web Push applies to installed Home Screen web apps](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/) after a user gesture and requires subscription plus a server sender. Delivery can be suppressed by permission, Focus, OS policy, power or connectivity; it is not an official emergency alert channel. [Background Sync has limited availability](https://developer.mozilla.org/en-US/docs/Web/API/Background_Synchronization_API). Offline install does **not** give live notices, offline Mapbox tiles, reliable push, or background evacuation routing. Link people to agency alert enrollment first.

## Read-aloud and provenance (your systems lane)

A possible ElevenLabs endpoint would accept a **source record ID and exact displayed-text hash**, not arbitrary user-provided text, and require an explicit tap. The server retrieves the verified publisher text, checks its version/freshness and allowed use, then calls [ElevenLabs TTS](https://elevenlabs.io/docs/api-reference/text-to-speech/convert) with the server-only [`xi-api-key`](https://elevenlabs.io/docs/api-reference/authentication). Never put `ELEVENLABS_API_KEY` in `NEXT_PUBLIC_*`, analytics, logs or browser requests. Do not send a resident address, household plan or unredacted report. ElevenLabs logging defaults on; zero retention is not a default feature. Apply caller/credit/length limits, consent, expiry and a text fallback. Return a trace (issuer, original record URL/ID, source times, checked time, text hash, voice/model ID and generation time) and label the audio **automated reading**, never an agency voice or newly generated instruction. Lane 1 owns the accessible speaker control and visible verbatim transcript. A screen reader or device speech option may be lower-cost and more private.

Any future **model projection** is a separate trust lane: scenario inputs and vintages, model/version, run time, validation, uncertainty, and reproducible method must be published next to its result. It is a conditional planning projection, not a current fire forecast or evacuation order. No model-produced number is currently in Firepoint.

### WindNinja model job: later research, never a live alert adapter

[WindNinja](https://github.com/firelab/windninja) has an official batch CLI, example `.cfg` files, build-from-source Dockerfile and C developer API, **not** a public hosted REST feed. Queue a pinned-release job runner rather than a browser call. Feed it a sourced, projected DEM and cited HRRR/station initialization; retain exact cycle/valid times, DEM vintage, model version, solver, grid, buffer, configuration hash, run time and output grid hashes beside each result. Schedule and compute costs, NOMADS availability, domain-edge error and failure/staleness states need an owner. Before any resident display, hindcast a Santa Ana case and compare mass and momentum solvers with canyon observations: fast mass-conserving runs may **underpredict lee-canyon winds**. A WindNinja grid is terrain-adjusted **wind planning context**, not a wildfire spread/arrival estimate, official warning, evacuation order or safe navigation path. A separate fire-spread model plus fuels, validation and uncertainty would be needed for conditional fire-arrival analysis. See the [deferred source queue](source-roadmap.md#deferred-model-source-windninja-research-queue-not-an-alert-api).

## Official routes and navigation handoff (research, not shipped)

Start with the issuer's exact published route or destination link, not an app-calculated “safe path.” Verify issuing agency, affected jurisdiction/zone, original notice/URL, publication/status times, public destination or agency route geometry, restrictions and retractions. If verified, after a tap Firepoint can offer a **destination-only** [Google Maps directions link](https://developers.google.com/maps/documentation/urls/get-started#directions-action) (`destination=` with no `origin`) or [Apple Maps link](https://developer.apple.com/library/archive/featuredarticles/iPhoneURLScheme_Reference/MapLinks/MapLinks.html) (`daddr=` with no `saddr`). Only an agency-listed public destination goes into the outbound URL; never a resident address, device point, saved area or personalized waypoint. The navigation app may then request its own location and compute a different route. Say clearly that its route is **not verified against fire, closures or evacuation instructions**; follow the agency's stated path. If no destination/route is verified, show only the official source link and “No route checked here.” [Ready.gov](https://www.ready.gov/evacuation) directs people to local authorities for designated routes. No route view or navigation link is implemented today.
