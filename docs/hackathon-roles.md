# Four-person hackathon scope (working split)

This is a **proposal**, not an assignment or a statement that missing integrations already work. The demo target is one defensible Glendale-area experience with direct official links, a local preparation list, and source-backed data only where coverage is verified. Tentative pilot: **Glenoaks Canyon as a City reference neighborhood**, not an evacuation zone or a risk ranking. Agree on the pilot with the team before presenting it as selected.

## Integration order

1. Keep the current source-first resident question and tentative pilot explicit. Each lane takes a focused branch and distinct files; the frontend and map owners agree on layout before moving the homepage. A real Mapbox public token must be provisioned and domain-restricted by the team; no token means a visible map-unavailable state, not an alternate invented layer.
2. Lane 3 publishes a versioned adapter contract with source coverage/provenance and failure fixtures. Lane 4 consumes those normalized records in an ingestion design (and keeps the source registry/last-good rule). Lane 2 publishes map attribution and **agency-verified** geometry evidence before overlay work. Lane 1 binds only validated DTOs; unavailable is the default.
3. Join on one walkthrough: save an area voluntarily → optionally open the basemap online → inspect each official source's actual checked/stale state (only after an adapter is connected) → follow the issuer link → edit checklist offline. Never infer an evacuation decision from the map.
4. Lane 4 may prototype text-exact ElevenLabs audio behind a bounded server endpoint **only after** a source-backed text view and consent exist. The UI owner supplies the button/transcript; the key, source trace and costs stay server-side. Community reports, automatic risk forecasts, voice assistants and evacuation routing stay parked until validation, rights and operating owners exist.

## Cross-review handoffs

- Frontend ↔ API: import `src/domain/contracts.ts`; never handwrite duplicate payload types. Include loading, down, stale, no-match and unconfigured states in screenshots. The UI owner does not need a backend key.
- Map ↔ API: Mapbox is display context only; never compute official zone membership from basemap tiles, a bookmark or camera center. Use issuing-agency polygons and document version/coverage. City `neighborhood_zones` are references only.
- API ↔ ETL: agree on `sourceKey`, issuer vs aggregator, original record ID/URL, geometry/coverage, source as-of, fetched/last-success, expiry/status, payload hash and contract version. The API adapter owns publisher parsing; the systems lane owns polling, atomic generations, last-good and evidence retention. Neither can promote a failed/blank fetch to safe.
- Systems/audio ↔ frontend: a read-aloud response must bind to a cited text/version, show the transcript and source before play, require a user action and degrade to text. `ELEVENLABS_API_KEY` stays server-side. Do not fabricate a voice announcement of an order.
- Route handoff ↔ API/map/UI: lane 3 confirms any agency-designated route or shelter ID/status/URL; lane 4 records validity, constraints and a public destination/issuer link; lane 2 may draw **publisher geometry only** after rights review; lane 1 lets the resident choose Apple Maps/Google Maps. Never include the resident origin in a Firepoint URL. The navigation app may calculate a different route and is not verified against fire, closures, capacity or orders. Do not label any computed route “safe.”
- Reports ↔ operations (parked): keep drafts on-device if no moderated server exists; publish no community pin from an unreviewed submission. Privacy and takedown must be designed together.
- Everyone: record source URL, issuer vs aggregator, vintage/checked time, geographic scope, license, and who tested the output. `npm run lint && npm run typecheck && npm test && npm run build` (or `make check`) are required but **not proof of emergency readiness**.
