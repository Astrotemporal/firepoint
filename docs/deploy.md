- The merged `/` routing prototype currently starts from a **simulated Verdugo fire**, unverified shelters hardcoded as `open`, invented "safe zones," private marks treated as fires, and automatic GPS permission. Its map/navigation output must be **removed from public rendering or gated off by default** before any Vercel production or publicly accessible preview. A disclaimer alone cannot turn those inputs into a verified route. Do not promote PR #11's three-mark "estimated fire" circle as a real perimeter.
- Production `POST /api/v1/{notices,context,hazards}/query` currently returns 503 **paused** before upstream contact (`src/server/live-query-gate.ts`). Keep that gate until source rights, freshness/caching, platform abuse limits and monitoring are reviewed. No evacuation feed, official standing zone lookup, confirmed open shelter, or safe route exists. A green build is not an emergency readiness certificate.
- Resolve the Mapbox browser token guard/error/offline states, fire-pin meaning, two-provider map overlap, service-worker offline wording and official-link prominence. Confirm license, attribution, privacy and billing. Offline shell ≠ live alert delivery.

## GitHub → Vercel setup (human-admin steps, no tokens here)

1. After the release gates, import `Astrotemporal/firepoint` using the [Vercel GitHub integration](https://vercel.com/docs/git/vercel-for-github). Framework: Next.js; root directory: repository root `./`; package manager: npm lockfile; production branch: `main`. **The first deployment of a new project is always production**, so do not connect a publicly accessible project while the simulated routing UI is present. Keep Git fork protection enabled.
2. In [Vercel environments](https://vercel.com/docs/deployments/environments), set `NEXT_PUBLIC_MAPBOX_TOKEN` for **Production only** to a new public `pk.` token restricted to the approved production origins. It is visible in browser bundles and rotates only after a redeploy. Do **not** use a secret `sk.` token. Mapbox URL restrictions on dynamic commit preview hosts are awkward: leave the Preview token unset (show an honest map-unavailable state) unless a separate, tightly restricted stable preview domain/token is set up. Review [Mapbox URL restrictions](https://docs.mapbox.com/help/getting-started/access-tokens/#url-restrictions) and [Mapbox pricing](https://www.mapbox.com/pricing/); do not allow every `vercel.app` site via a broad restriction.
3. Leave `NWS_USER_AGENT`, `AIRNOW_API_KEY`, `GLENDALE_GIS_MCP_KEY`, and `ELEVENLABS_API_KEY` **unset** in Preview/Production until each server use is reviewed. If later needed, use server-only [sensitive environment variables](https://vercel.com/docs/projects/environment-variables/sensitive-environment-variables) in Production, not `NEXT_PUBLIC_*`. `FIREPOINT_DEMO_LIVE_SOURCES` must **never** enable a Vercel deployment: the code checks `NODE_ENV !== "production"`, so both Preview and Production builds stay paused. Do not replace it with `VERCEL_ENV === "preview"`; preview URLs can be public. `.env.local` is ignored and remains only on the developer machine.
4. Turn on [Deployment Protection](https://vercel.com/docs/deployment-protection) for previews (Vercel Authentication + Standard Protection). Review the actual generated production domain too; `*.vercel.app` links are not automatically private. If you later automate protected-page smoke tests, store `VERCEL_AUTOMATION_BYPASS_SECRET` in GitHub Secrets only and send it in the documented bypass header. Never print it.
5. Add a GitHub `main` ruleset with required PR review and CI `web` check before allowing [v0 GitHub import](https://v0.app/docs/github). v0 imports this repository into a chat/sandbox and auto-pushes a **working branch**; publishing a PR that merges into `main` can release to production. Treat v0's automated "Fix CI" as untrusted code until reviewed; keep source-policy, map and deployment changes under owner review. **v0 is a design/code tool, not an authority for emergency data.**
6. Decide how to handle `.github/workflows/preview.yml`: it currently commits screenshot PNGs to `main`, which can trigger a Vercel production rebuild and may conflict with a PR-only branch rule. Options: make screenshots CI artifacts instead of bot commits, or configure an [Ignored Build Step](https://vercel.com/docs/deployments/configure-a-build#ignored-build-step) after testing that only doc/screenshot changes are skipped. Do not assume `[skip ci]` stops Vercel. Optional [staged production](https://vercel.com/docs/deployments/promoting-a-deployment) lets a human review before assigning a custom domain; verify behavior for the generated `*.vercel.app` URL rather than treating it as private.

## Deploy verification to add when a project exists

Record a deployment URL and Git SHA, then check `/`, `/prepare`, `/manifest.webmanifest`, `/sw.js`, `/offline.html` and the three personalized POST routes. The routes must return 503 with the explicit **paused** state on a production build; a 200 live response fails the gate. Use a synthetic **test request body only**, not a resident point, and do not call upstream data sources in CI. A browser check must find **no simulated fire, fake open shelter, invented safe zone, crowd-derived perimeter, or safe-route claim** before public access. After that, a [Vercel deployment webhook](https://vercel.com/docs/webhooks) can trigger a protected GitHub smoke workflow bound to a known deployment SHA/host. Do not accept an arbitrary event-supplied URL for a privileged fetch without host validation.

There is no CLI `vercel deploy` job yet. Vercel's Git integration can build Next.js from the checked-in npm scripts without storing a `VERCEL_TOKEN` in GitHub. A public preview or production URL is still a **development deployment** until the agency/source and operations review is complete.
