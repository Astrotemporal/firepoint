Source adapters exist but production personalized POST routes intentionally return 503. Offline shell access is not offline alert delivery.
- For a candidate SHA, check `/`, `/prepare`, `/manifest.webmanifest`, `/sw.js`, `/offline.html`, and all three `/api/v1/{notices,hazards,context}/query` POST routes with a synthetic request. The POSTs must return 503 **paused**, not a surprise 200 live feed. Review the browser UI for fake incidents/statuses or safety promises; a green build alone is not a release certificate.

Vercel Hobby is for non-commercial personal use; confirm the plan before sponsored/municipal operation. Source rights, rate limits, monitoring, attribution and agency review must precede public live-source use.

## Community reporting preview gate

**Environment inventory (2026-09-28, names and targets only; values not inspected).** In `ex-ars/firepoint`, all 16 Neon-integration database variables (`DATABASE_URL`, `DATABASE_URL_UNPOOLED`, `POSTGRES_URL*`, `PG*`, `POSTGRES_*`, `NEON_PROJECT_ID`) are single entries that target **both** Preview and Production, with no Git branch override. Per-PR Neon branches come only from the integration's automatic Preview deployment action. So, do **not** disable automatic Preview branching before you add Preview-scoped database variables for a dedicated staging branch: without them, Preview deployments would use the Production database settings. This inventory does not show whether Preview and Production connection values differ. No `FIREPOINT_REPORTING_ENABLED` variable exists in any environment, so report routes stay off.

Community reporting must stay disabled in Production. If Neon attaches `DATABASE_URL` to both Preview and Production, that alone must not enable reporting. The report routes require `FIREPOINT_REPORTING_ENABLED=preview-only` and `VERCEL_ENV=preview` before any database access. Do not set that flag until Preview protection is confirmed, Preview/Production Neon database or branch separation is confirmed by the owner, this project is confirmed not to use Enterprise Trusted Proxy/custom ingress behavior that changes Vercel's documented request-header handling, and retention purge is demonstrated. Vercel Cron runs on Production only and is not sufficient for the Preview-gated purge route. Owner may verify an external Preview purge caller, or an optional Neon Scheduled Function Trigger on the Preview branch; Neon `pg_cron` is not preferred for autosuspend/free-tier expectations because Neon documents it only runs while compute is active. Do not collect real teammate location data until a deletion job is observed working. See [community reporting preview](community-reporting-preview.md).
